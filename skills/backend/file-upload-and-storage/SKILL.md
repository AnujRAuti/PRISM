# File Upload and Storage

## 1. Purpose

Accept files without letting them become an attack path or a cost problem. Uploads bring five distinct risks: malicious content (webshells, macro documents, polyglots), path traversal and overwrite, unbounded size and cost, unauthenticated access to private objects, and leaked metadata (EXIF GPS, author names). This skill covers the upload flow, validation, storage layout, access control, and lifecycle.

**Scope:** storage you own. Uploads are untrusted input by definition; never execute, render inline from the same origin, or trust a client-declared MIME type. Destructive retention or bulk-delete operations require explicit authorization.

## 2. Activation Conditions

- Adding avatar, document, media, or export upload features.
- Files served from the app domain and could execute (HTML/SVG).
- Users report access to files they should not see.
- Storage costs growing without retention rules.
- Keywords: file upload, presigned URL, S3, multipart, MIME sniffing, magic bytes, path traversal, EXIF, virus scan, signed URL, object storage, retention.

## 3. When Not to Use

- Small text fields (store in the database).
- Files generated by your own system with no third-party input (still need access control, less validation).

## 4. Required Context

1. Object store and CDN (S3, GCS, Azure Blob, MinIO) with credentials model.
2. Allowed file types, maximum sizes, and who may upload.
3. Access model: public, authenticated, per-tenant, per-document sharing.
4. Compliance needs (retention, deletion, virus scanning).
5. Client types (browser, mobile) and their upload capabilities.

## 5. Operating Procedure

1. **Never proxy large uploads through the API** when avoidable: issue a presigned `PUT` scoped to an exact key, content length range, and short expiry.
2. **Generate the object key server-side**: `tenant/<tenant_id>/<yyyy>/<mm>/<uuidv7>.<ext>`. Never accept a client-supplied path or filename as the key.
3. **Constrain the presigned policy**: content-length range, required content type, and expiry ≤ 15 minutes.
4. **Validate on completion, not trust at upload**: HEAD the object, check size and magic bytes server-side, and reject mismatches by deleting the object.
5. **Encode or strip filenames**: store the original name as metadata only, sanitize for display, and always send `Content-Disposition: attachment` for non-media types.
6. **Serve from a separate domain or with `Content-Security-Policy: sandbox`** so a malicious HTML/SVG cannot run with your origin's cookies.
7. **Scan for malware** before making files available to other users; quarantine in a separate prefix/bucket.
8. **Strip metadata** (EXIF) from images and re-encode to a known-safe format.
9. **Authorize every download**: signed URLs with short TTL, or a streaming endpoint that checks policy per request.
10. **Set lifecycle rules**: transitions to cold storage, expiry of temporary uploads, and deletion honoring user erasure requests.
11. **Quota per tenant and per user**; alert on abnormal growth.

## 7. Practical Implementation

**Presigned upload with a server-generated key and hard limits:**

```python
import uuid
from datetime import datetime, timezone
import boto3
from botocore.config import Config

s3 = boto3.client("s3", config=Config(signature_version="s3v4"))

ALLOWED = {"image/jpeg": ".jpg", "image/png": ".png", "application/pdf": ".pdf"}
MAX_BYTES = 10 * 1024 * 1024

def create_upload(principal, filename: str, content_type: str, size: int) -> dict:
    if content_type not in ALLOWED:
        raise ValueError("content type not allowed")
    if not (0 < size <= MAX_BYTES):
        raise ValueError("size out of range")

    now = datetime.now(timezone.utc)
    key = f"tenant/{principal.tenant_id}/{now:%Y/%m}/{uuid.uuid4()}{ALLOWED[content_type]}"

    post = s3.generate_presigned_post(
        Bucket=BUCKET,
        Key=key,
        Fields={"Content-Type": content_type},
        Conditions=[
            {"Content-Type": content_type},
            ["content-length-range", 1, MAX_BYTES],
        ],
        ExpiresIn=600,
    )
    return {"upload": post, "key": key}
```

**Verify the uploaded object by magic bytes and size (client MIME is a claim, not a fact):**

```python
import filetype

def inspect_object(key: str) -> dict:
    head = s3.head_object(Bucket=BUCKET, Key=key)
    size = head["ContentLength"]
    if size == 0 or size > MAX_BYTES:
        s3.delete_object(Bucket=BUCKET, Key=key)
        raise ValueError("invalid size")

    magic = s3.get_object(Bucket=BUCKET, Key=key, Range="bytes=0-4095")["Body"].read()
    kind = filetype.guess(magic)
    if kind is None or kind.mime not in ALLOWED:
        s3.delete_object(Bucket=BUCKET, Key=key)
        raise ValueError("content does not match an allowed type")
    return {"size": size, "mime": kind.mime, "ext": kind.extension}
```

```python
async def finalize_upload(session, key: str, declared_name: str, principal) -> Document:
    info = inspect_object(key)
    if not info["mime"].startswith("image/"):
        scan_result = await scan_with_clamav(key)     # copy to quarantine bucket first
        if scan_result.infected:
            s3.delete_object(Bucket=BUCKET, Key=key)
            await security_log.warn("upload_infected", key=key, principal=principal.user_id)
            raise ValueError("file rejected by malware scan")

    doc = Document(
        id=str(uuid.uuid4()), tenant_id=principal.tenant_id, owner_user_id=principal.user_id,
        object_key=key, display_name=sanitize_name(declared_name),
        mime=info["mime"], size_bytes=info["size"], status="available",
    )
    session.add(doc)
    await session.commit()
    return doc
```

**Strip EXIF and re-encode images:**

```python
from PIL import Image, ImageOps
import io

def sanitize_image(raw: bytes) -> bytes:
    img = Image.open(io.BytesIO(raw))
    img = ImageOps.exif_transpose(img)          # honor orientation, then discard metadata
    clean = Image.new(img.mode, img.size)
    clean.putdata(list(img.getdata()))
    out = io.BytesIO()
    clean.save(out, format="JPEG", quality=85, optimize=True)
    return out.getvalue()
```

**Download authorization with a short-lived signed URL:**

```python
@router.get("/documents/{doc_id}/download-url")
async def download_url(doc_id: str, principal: Principal = Depends(require_user),
                       session=Depends(get_session)):
    doc = await session.get(Document, doc_id)
    if doc is None or doc.tenant_id != principal.tenant_id:
        raise HTTPException(404)                       # do not disclose existence
    authorize(principal, Action.DOCUMENT_READ, doc)
    url = s3.generate_presigned_url(
        "get_object",
        Params={"Bucket": BUCKET, "Key": doc.object_key,
                "ResponseContentDisposition": f'attachment; filename="{safe_ascii(doc.display_name)}"',
                "ResponseContentType": doc.mime},
        ExpiresIn=300,
    )
    return {"url": url, "expires_in": 300}
```

**Safe serving headers for user content (if served from your domain):**

```python
response.headers["Content-Security-Policy"] = "sandbox; default-src 'none'"
response.headers["X-Content-Type-Options"] = "nosniff"
response.headers["Content-Disposition"] = "attachment"
response.headers["Cache-Control"] = "private, max-age=60"
```

Prefer a separate cookieless domain (e.g. `files-usercontent.example.net`) so XSS in a file cannot reach your session cookies.

**Key validation to defeat traversal and overwrite:**

```python
import posixpath

def is_safe_key(key: str, tenant_id: str) -> bool:
    if key.startswith("/") or "\\" in key or ".." in key.split("/"):
        return False
    norm = posixpath.normpath(key)
    return norm.startswith(f"tenant/{tenant_id}/") and norm == key
```

## 8. Quality Standards

- Object keys are server-generated, tenant-prefixed, and never derived from user filenames.
- Presigned policies include content type and content-length range; uploads expire quickly.
- Content is validated by magic bytes and size after upload; mismatches are deleted.
- Files are malware-scanned before being served to other users.
- All downloads are authorized per request; URLs expire in minutes.
- User content is served with `nosniff`, `Content-Disposition: attachment`, and a sandboxing CSP, ideally from a separate domain.
- Image metadata is stripped; original names are stored as metadata only and escaped on display.
- Lifecycle, retention, and quota rules exist per bucket/tenant.

## 9. Verification and Testing

- Upload a `.php`, `.html`, and SVG with script, all renamed to `.jpg`; all must be rejected by magic-byte validation.
- Upload an oversized file (over the limit) and confirm rejection at the policy level, not after storage.
- Attempt path traversal in a filename (`../../etc/passwd`) and confirm the key is server-generated regardless.
- Attempt to download another tenant's document; expect `404`.
- Verify signed URL expires (wait or shorten TTL in a test) and cannot be reused after expiry.
- Confirm EXIF GPS data is absent from a processed image.
- Test quarantine flow with an EICAR sample in an isolated environment only.

## 10. Security Considerations

- Never trust `Content-Type` or file extensions from the client; verify bytes server-side.
- Never serve user files from the same origin without `nosniff` and an attachment disposition; active content can steal cookies.
- SVG is executable content (scripts, external references); sanitize with a library or disallow.
- Zip bombs and PDF bombs: enforce decompressed-size limits and processing timeouts.
- Presigned URLs are bearer tokens: keep TTLs short, never log them, and never place them in referrers.
- Bucket policies must block public access unless intentional; verify with an anonymous request test.
- Server-side request forgery risk if you fetch remote URLs supplied by users; allowlist schemes/hosts and block internal ranges.
- Object metadata can leak original paths, usernames, and EXIF; strip before distribution.

## 11. Failure Handling

- **Upload succeeds but finalize never runs:** orphaned objects — add a sweeper for keys without a database row older than 24 h.
- **Large file times out:** use multipart uploads via presigned part URLs; do not stream through the app.
- **Duplicate objects for retries:** the client re-uploads; key by content hash where dedupe matters.
- **Malware scanner unavailable:** keep files quarantined and unavailable; never fail open to "available".
- **Deleted row, object remains:** use a deletion job driven by a tombstone table; storage deletion is asynchronous and must be retried.
- **Cost spike:** missing lifecycle rule or a public endpoint being abused; add quotas and rate limits.
