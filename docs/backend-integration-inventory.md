## Data, dependencies and infrastructure

- **Database:** PostgreSQL 15; PostGIS and pgvector extensions. SQLAlchemy models and Alembic migrations are in `backend/db/`, `alembic/`, and `docker/pg-init/`.
- **Queue/cache:** Redis 7 for analysis jobs and worker queue behavior.
- **Object storage:** S3 API through boto3; Compose provisions MinIO and private quarantine/evidence buckets. No AWS account-specific resources are configured by the code; S3-compatible AWS could be configured via endpoint/credentials.
- **Identity:** optional OIDC/JWKS token verification, including Supabase as a possible identity provider. Backend provisions managed application identities/roles in its own PostgreSQL schema; it does not rely on Supabase DB/Auth/Storage/Realtime/Edge Functions as the data plane. Current frontend includes Supabase JS but uses mock fallbacks.
- **ML / image processing:** PyTorch CPU, Transformers/CLIP, Ultralytics YOLO, Pillow, imagehash, NumPy, EXIF extraction. Model downloads/weights and CPU resources are runtime considerations.
- **Observability:** Prometheus-compatible metrics, structured logging, health/readiness probes, tracing/redaction modules.
- **External service integrations:** application-level external-system/client credentials and outbound webhooks; no hard-coded payment, email, AI SaaS, or analytics provider identified in dependencies.
- **Deployment:** Dockerfile, Docker Compose, PostgreSQL initialization, Redis, MinIO, explicit migration profile; no Terraform/IaC or GitHub Actions workflow found in the checkout.
